<objective>
Close the Phase 12 verification gap CR-01, which blocks PIN-01, and fold in WR-01, which has the same root cause and serves PIN-02. Both checks must bind the working tree to the committed blobs directly. `git status` is not enough on its own.

Purpose: Phase 13 runs `--validate --at-pin` at the publication commit before it writes the permanent publication record. Today that gate rests only on `git status --porcelain`. That call cannot see the following, so at-pin can print PASS on a tree that is not the pinned tree:
- ignored or untracked files under `generated/`, which holds all 7 generated publication files;
- a publication file that a committed `git rm --cached` dropped from HEAD;
- skip-worktree and assume-unchanged edits, including edits to the publisher script;
- anything when `status.showUntrackedFiles=no` is set.

The output would also falsely claim that only PUBLICATION_RECORD_BINDING is deferred. This plan makes at-pin compare every pinned path against the HEAD blob, reject index flags, and harden the status call. It ties plain mode's working tree to HEAD with the same function, and adds real-layout git tests.

Output: one publisher code commit plus one test commit. Each commit gets a ledger section in 12-BASELINE-RED.md that shows the red set is unchanged (D-16).

Decisions honoured: D-04 is extended, not replaced. The hardened `git status --porcelain` stays as the second line, and the HEAD-blob comparison is added in front of it. D-05: the 10-file `publication_paths()` list is reused unchanged. D-06: plain mode keeps ancestry and pub-vs-HEAD blob identity, and adds working-tree-vs-HEAD. D-08 and D-12: at-pin covers the 10 paths plus the publisher script, and plain mode's working-tree binding stays at the 10 files because D-07 covers the script. D-16: the red ledger.

Deferred, with no code change in this plan:
- WR-02 (`GIT_*` environment scrubbing and `GIT_CONFIG_NOSYSTEM`) is not trivially safe. On this machine `core.autocrlf=true` comes from both the Git for Windows system config and the repo config. Scrubbing ambient config changes how status and CRLF behave in the operator's tree, and it needs its own test design. It stays advisory.
- WR-03 (the D-10 subprocess test is vacuous while `--validate` is red) goes to Phase 13 as a follow-up. Once validator 1 is green at the record commit, assert `before == (0, 'PASS')`.
- IN-01..IN-04, IN-06 and IN-07 stay advisory.
