## Previous Gap and How It Was Closed

**Previous gap (CR-01, truth 2, BLOCKER):** the at-pin clean-tree check relied only on `git status --porcelain -- <paths>`. That command printed nothing in four cases:
- ignored or untracked files under the gitignored `generated/`;
- a publication file dropped from HEAD by a committed `git rm --cached`;
- skip-worktree or assume-unchanged edits, including edits to the publisher script;
- `status.showUntrackedFiles=no`.

In every case, at-pin could print PASS for a tree that was not the pinned tree. No test used the real layout (WR-04).

**Closure (12-08, d7a98f7):**
- New `check_tree_matches_head(paths)`. For each path it requires:
  - the path is committed at HEAD (`git cat-file blob <head>:<p>` through `git_commit_blob`, which validates the SHA and path first);
  - the live file exists;
  - `lf_bytes(live) == lf_bytes(HEAD blob)`.

  It then requires every path's `git ls-files -v` tag to be `H`. Lowercase (assume-unchanged), `S` (skip-worktree), `M` (unmerged) and "not in the index" all fail closed.
- At-pin (`validate_published`, L793-797) runs `git_not_shallow()`, then `check_tree_matches_head` over the 10 D-05 paths plus the publisher script, then the hardened `git_dirty`. `git_dirty` runs `git --literal-pathspecs status --porcelain --untracked-files=all --ignored=matching` over the same 11 paths plus the OUT folder. The error texts now describe what is actually checked.
- WR-01: plain `--validate` now ends `check_publication_record` with `check_tree_matches_head(publication_paths())` (L857).
- IN-05: the pathspecs are literal, and `git_run`'s OSError message names the git subcommand.
