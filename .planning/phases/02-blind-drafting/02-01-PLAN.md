<objective>
Build the validator and the two emitted schemas for the Phase 2 proposals file and the later drafting record.

Purpose: the drafter's output must be checkable mechanically (so the user never has to read proposal content before the drafting commit, D-20) and so the brief in plan 03 can point at one output format.
Output: one script, two schemas. Nothing is committed by this plan; plan 02 adds tests and makes the single tooling commit.

Decisions settled here (the research left them open):
- The proposals file is written verbatim from the drafter (no sort_keys re-dump, per D-15/D-17). The validator parses it and does not require sorted keys. dump() is used only for the emitted schemas.
- catalog_fingerprint is computed so it is immune to line-ending conversion (autocrlf is on): git_blob_id from `git hash-object` of the working catalog; sha256 over the bytes of `git cat-file blob <that id>`.
- This plan prescribes its own commits. Do not make any per-task commit.
</objective>
